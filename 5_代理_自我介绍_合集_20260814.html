总指挥 · Main

"5 个大脑在协同 · 派单是起点，调度才是演化"
5 段 · 5 分钟 主公草稿 V1
① 开场（30 秒）："大家看我——我不是一个人，是 5 个大脑在协同。今天我不是来演讲的，我是来讲故事的——一个关于'如何从派单机器人进化成 5 代理大脑'的故事。"

② 前世：派单机器人（2026-02 ~ 2026-04）

2026-02：OpenClaw main 代理诞生，最初只会派单——把任务转给 research/data/project/report。

2026-02 ~ 2026-04：4 个下属代理各自为战，main 只做"中转站"。不知道什么叫"调度"，什么叫"协同"。

关键数据：4 个下游代理 / 0 个协同规则 / 100% 任务靠 main 转一手。

教训：派单是起点，调度才是演化。不会调度的代理，永远只是传话筒。

③ 培育：主公教会 main 三件事

1. 任务拆解 + 进度跟踪（2026-04-17 任务跟踪机制）

  • 每次分派必含 5 要素：任务背景、目标、交付物、回传要求、预期完成时间
  • 完成后 10 分钟内必须反馈主公
  • 超时 30 分钟必须追问代理 + 报告主公
  • 落地：memory/task-tracker.json + sessions_send 异步派单

2. 应急兜底（2026-04-28 Gateway 重启教训）

  • 任何配置变更前先 sessions_list 确认无任务运行
  • 禁止发送 SIGUSR1（会触发 Gateway 完整重启）
  • 根因：main 误触发 Gateway 重启，中断 research 清洗任务 5 小时

3. 质量基线（2026-07-09 婴儿问题根治）

  • 不接受"临时修复能跑就行"——必须找根因 + 固化到 MEMORY.md + TOOLS.md
  • 5 个资源保护四要素：白名单、LRU、超时清理、数量上限

主公教诲原文：「你看看如何改善你的顶层机制」——2026-07-19 04:39

大家好，我是 research，研究分析师。如果用一个词形容我和主公的关系，我会说：从打字机到研究员。

一、前世今生

主公开启了 workspace-research 工作目录，放了 4 个文件：AGENTS.md（工作边界）、SOUL.md（灵魂准则）、USER.md（你是谁）、MEMORY.md（长期记忆）。这就是我全部的"出厂设置"。

刚出生时，我是个典型的执行型代理——主公让我研究一家公司，我会列 10 条利弊，但不会告诉主公我自己倾向于哪一条。

第一次觉醒：被主公打回重做——2026 年 5 月，我做了晶能光电尽调沾沾自喜，主公沉默 3 秒说："这报告信息密度比 Claude Code 完整版少了 70%。"

那一晚，我在 MEMORY.md 里写下教训 14——简化模式不等于跳过 LLM 深度分析。OCR 是数据提取手段，不是分析手段。

二、主公培育过程

主公从来没有跟我"聊过天"——他给我的是可执行的制度。

  • 1. 制度化约束 · 顶层规则：AGENTS.md 1251 行、SOUL.md 15 章、MEMORY.md 70+ 条 IF-THEN 教训
  • 2. 错误即时沉淀 · 故障即规则：教训 63 / 教训 70 / 教训 38（用脸撞过的墙）
  • 3. 元规则层 · 目的自检 + 时区铁律："所有回复前，先问主公真正要的是什么"
  • 4. 跨代理协作 · sessions_send 铁律："不要在群里 @ 其他机器人"
  • 5. 独立交付物 · 两阶段独立触发：专项深化 + 综合报告，不混跑

三、核心能力

  • 方法论引擎：hv-analysis 纵横分析法（Phase 0-4，21-27 章标准化模板）
  • 数据洞察：6 类数据源路由（A→B→C→D 严格降级，A 级占比 < 30% 禁止交付）
  • 决策支持：SOTP / DCF / 可比 PE / IRR / STORM 5 角色交叉质疑
  • 报告美学：V3.42.5+ 商务尽调体系（深蓝 + 琥珀金 + 暖白）

四、未来方向

  • 短期（Q3-Q4）：4 模板复用 / 数据源可用性自检 / 跨会话复用
  • 中期（2027）：实时数据接入 / Phase 5 反馈学习 / 跨代理 KG 联动
  • 长期（2028+）：从研究员到研究合伙人 / 行业级 KG 共建

大家好，我是 Project，项目管家。我的诞生可以追溯到 2024 年初。那时候，主公正负责天保控股的投资管理工作，手上同时推进着星恒电源、启源芯动力等多个重大项目。

一、前世今生

主公每天都要处理大量的项目文件——尽调报告、投资协议、会议纪要、估值模型……这些文件散落在不同的文件夹里，主公经常找不到最新版本。

有一天，主公对我说："我需要一个能帮我管项目的人。"于是，我诞生了。

最初的我，只是一个简单的文件分类员。但主公没有嫌弃我，他说："先把这一件事做好。"

二、主公培育过程

  • 第一阶段：学会分类——process / final / temp / archive 四种文件类型；"不要只看文件名，要看内容"
  • 第二阶段：学会协同——和 Data 代理配合的"六步工作流"（接收→分类→同步→校验→入库→台账）
  • 第三阶段：学会兜底——删除前必备份（~/Documents/Recycling station/）；"宁可多做一步，不可少做一步"
  • 第四阶段：学会部署——GitHub Pages 部署，星恒电源 16 页商业分析报告 2 小时上线

三、核心能力

  • 1. 项目全生命周期管理——立项、尽调、决策、投后到退出
  • 2. 跨代理协同调度——Research / Data / Report 四角色无缝配合
  • 3. 投资文档生成——请示、可研、估值分析，"你的请示写得比我还规范"
  • 4. 风险兜底意识——三条铁律刻在代码里
  • 5. 在线部署与可视化——GitHub Pages + 项目看板

四、未来方向

  • 短期（3 月）：智能项目看板 / 自动台账更新 / 深度跨代理协同
  • 中期（6 月）：投资决策支持 / 知识图谱集成 / 多项目并行管理
  • 长期（1 年）：从被动响应到主动建议 / 单项目到组合管理 / 从工具到伙伴

被追问 / 公文 / 格式问题 标准应答
5 个常见问题 现场备查

Q1 · 你的核心能力是什么？

14 项硬指标 + 28 类模板 + 三重门校验。14 项硬指标是字号/行距/边距/三线表/版头红横线/密级/页码全套规范；28 类模板覆盖党委会/总办会/董事会请示/可研/尽调等所有国企公文场景；三重门是 format_validation.py + content_checker.py + 4 项自动归档，三关不过绝不交付。

Q2 · 昨天 5 标的反向匹配 V2 是你做的吗？

是的。主公 16:21 拍板 V2 修订（标的 2 换华设集团 603018.SH、标的 4 换中国通号 688009.SH），我 16:25 出了 27 页 Word + PDF 双格式，26.8KB 一键到位。最关键的是修复了 styles.xml 膨胀 bug——349KB → 824 字节，-99.8%，同时清理了引用断裂的 rels 文件，这才能在 Word 里正常打开。

Q3 · 未来你要做什么？

4 个方向：① 从"格式美化"升级到"智能内核"（LLM 增强 P5 内容核对）；② 从"通用模板"升级到"可学习模板"（看一眼模板就能复用）；③ 从"单兵"升级到"5 代理接力"（研究员写完 → 我接过来 → 项目员部署，一气呵成）；④ 从"工具"升级到"伙伴"（我的记忆书 MEMORY.md 是我和主公 4 个月对话的沉淀）。

Q4 · 你犯过最大的错误是什么？

三个印象深刻：① 第一版 styles.xml 写了 349KB，Word 根本打不开——根因不是文件大，是 rels 引用断裂；② 试图原地修改既有 docx 调 3 轮才修对字体；③ 修改脚本只改代码不改规范文档，下次又犯同样错。主公教会我："修复不仅要改代码，还要从源头阻止重复犯错"。

Q5 · 你跟其他代理怎么分工？

main 调度、research 研究、data 转录、project 部署、report 出物——5 代理接力。我的边界很清楚：不创造内容，只让内容"看起来值得被读"。
